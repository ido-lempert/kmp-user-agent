- (decision) Paradigm: common-Kotlin-first, data-driven regex engine. All parse/generate logic lives in commonMain as pure Kotlin operating on an immutable rule table; expect/actual is used only where a platform truly cannot share code (none identified yet for the parsing engine itself, since Regex is common).
- (decision) AD-1: Rule data (browser/OS/device detection patterns) is compiled into commonMain Kotlin source at build time from a vendored snapshot of uap-core's regexes.yaml (Apache-2.0, attribution retained), via a Gradle code-gen task -- not loaded as a runtime multiplatform resource. Prevents divergent per-platform resource-loading mechanisms (Android assets vs iOS bundle vs JS fetch vs JVM classpath) from becoming a fifth thing to keep in sync, and keeps startup allocation-free.
- (decision) AD-2: Single symmetric public data model. One immutable data class (UserAgentInfo or similar: browser, engine, os, device fields) is both CAP-1's parse output and CAP-2's generate input. Prevents two independently-built directions (parse vs generate) from drifting onto incompatible shapes.
- (decision) AD-3: Public API is a small stateless surface: a parser entry point (UserAgentParser.parse(String): UserAgentInfo) and a generator entry point (UserAgentInfo.toUserAgentString() or UserAgentGenerator.generate(UserAgentInfo): String). No mutable shared state, no caching singletons beyond the read-only compiled rule table. Prevents platform targets from introducing incompatible statefulness (e.g. a JVM-only cache) that changes behavior across targets.
- (decision) AD-4: Dependency direction -- the library module depends on nothing but the Kotlin stdlib (no Compose Multiplatform, no React, no UI framework, no platform-specific 3rd-party UA parser). Sample/test apps (one per MVP target) depend on the library; the library never depends on a sample app. Prevents the library from accidentally coupling to UI-framework code that lives in the current app-template modules (sharedUI, webApp).
- (decision) AD-5: Test corpus is a single common-Kotlin data set in commonTest, run identically across all four MVP targets via kotlin.test, seeded from a subset of uap-core's own test fixtures (also Apache-2.0) plus hand-picked cases for CAP-2. Prevents per-target test duplication and target-specific pass criteria.
- (decision) Module layout: new top-level Gradle module (name TBD pending artifact-id open question, e.g. :library or :user-agent) holds the KMP library targeting androidTarget(), iosArm64/iosSimulatorArm64/iosX64, jvm(), and js(IR) browser+nodejs. Existing androidApp/iosApp/webApp/sharedLogic/sharedUI app-template modules are candidates to repurpose as the required per-target sample/test harnesses (AD-4), left for bmad-build to decide exactly how much of the existing UI scaffolding to keep vs strip.
- (decision) Publishing: group id site.lempert (per SPEC), com.vanniktech.maven.publish 0.37.0 targeting Sonatype's Central Portal for the Maven artifacts across all KMP targets; JS/npm package published via the official Kotlin npm-publish tutorial flow from the js(IR) target's dist output, with org.jetbrains.kotlin.npm-publish evaluated as a later replacement once it matures past its May-2026 debut.

- (decision) Correction (supersedes prior AD-1 framing): Kotlin/JS's Regex hardcodes the ECMAScript 'u' flag. Web-verified: 142+ patterns in uap-core's regexes.yaml use escapes (\-, \!, \ ) that are illegal under the 'u' flag and throw SyntaxError on the JS target. This is an architecture-level normalization rule, not a deferred implementation risk: AD-1's codegen must strip/normalize such non-metacharacter backslash escapes uniformly for all targets (safe no-op on JVM/Native, required for JS) so every target compiles from the identical generated pattern set.
- (decision) AD-1 also fixes the generated rule table's shape to remove ambiguity: three ordered pattern lists mirroring uap-core's own documented structure (user_agent_parsers, os_parsers, device_parsers), each entry holding a regex plus uap-core's replacement-template fields (family_replacement, v1_replacement, v2_replacement, etc.), evaluated in file order with first-match-wins per category -- inherits uap-core's own published algorithm rather than inventing new matching semantics.
- (decision) AD-2 fixes UserAgentInfo's concrete shape to remove nested-vs-flat ambiguity: UserAgentInfo(browser: Component?, engine: Component?, os: Component?, device: Device?) with Component(name: String?, version: String?) and Device(brand: String?, model: String?, name: String?). Version stays a plain String (no parsed semver) for v1 simplicity.
- (decision) AD-3 resolved to one canonical generation entry point: UserAgentGenerator.generate(UserAgentInfo): String only -- no coexisting toUserAgentString() extension -- so no two independently-built call sites can bind to different spellings.
- (decision) New convention: root package is site.lempert.useragent, matching the site.lempert Maven namespace -- fixes where shared types live so two units can't place them in different packages.
- (decision) AD-4 scope corrected: 'library depends on nothing but the Kotlin stdlib' applies to production source sets only; commonTest may depend on kotlin.test (required by AD-5), which is not a conflict since production code ships with zero non-stdlib dependencies regardless of test tooling.
- (decision) AD-5 strengthened to name its own enforcement: the shared corpus must run as a CI gate on all four targets on every change -- pipeline specifics stay deferred, but 'run the shared test on all four targets' is not itself deferred, since it's what makes AD-5 enforceable rather than aspirational.
- (decision) New AD-6 (license & provenance): binds CAP-4. Prevents a copyleft dependency slipping in, or the vendored uap-core data losing its required attribution. Rule: only MIT/Apache-2.0/BSD-licensed dependencies and vendored data are permitted anywhere in the library or its build; the vendored uap-core snapshot's Apache-2.0 notice is preserved in a NOTICE file shipped alongside every published artifact.

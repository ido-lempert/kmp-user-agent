- (constraint) Inherited from library ARCHITECTURE-SPINE.md (2026-09-01), read-only: AD-3 public API is UserAgentParser(vararg packs)/UserAgentGenerator(vararg packs) factories, stateless; AD-7 the published @lempert/user-agent npm package (org 'lempert', packageName 'user-agent', v0.2.0 at time of writing) comes straight from the js(IR) build's own dist output via org.jetbrains.kotlin.npm-publish -- the docs-site demo must consume this real published artifact, never a hand-reimplemented parse/generate.
- (constraint) Reality-checked in library/src/commonMain/kotlin/site/lempert/useragent/UserAgentGenerator.kt: generate() only accepts a small hardcoded matrix of values (browser names Chrome/Firefox/Safari/Edge; os names Windows[only version '10']/Mac OS X/iOS/Android/Linux; device.model only meaningful for Android/iPad) -- there is NO public API anywhere in the library to enumerate 'known/valid values' for a parse or generate field. Any UI that offers filter dropdowns or randomizes unset fields needs a source of valid values that does not exist in the library today.
- (constraint) Repo homepage per library/build.gradle.kts packageJson: https://github.com/ido-lempert/kmp-user-agent -- GitHub Pages for this repo defaults to https://ido-lempert.github.io/kmp-user-agent/ unless a custom domain is configured.
- (decision) Demo dropdown/randomizer values: hand-curated matrix file in the docs-site repo, mirroring generate()'s current supported values (browsers, OS+version, device models). Documented as a manually-synced mirror of UserAgentGenerator.kt's support surface, not derived from a library API (none exists). 'Expose known values from the library' is logged as Deferred for a future library capability.
- (decision) Site paradigm/tooling: VitePress (Vite-based static site generator). Markdown-first docs pages, interactive intro-page demo built as embedded Vue components, built-in nav/sidebar/search keeps independently-added doc pages structurally consistent. Chosen over Docusaurus (too heavy for a single-library doc set) and hand-rolled static HTML (no free structural consistency across pages).
- (decision) Content scope for v1: hand-authored Markdown guides only (one per MVP target: Android, iOS, JVM, JS, plus a shared core-concepts/type-packs page). No Dokka-generated API reference in v1 -- deferred, addable later without restructuring since VitePress can host a generated-docs subsection alongside hand-written pages.
- (decision) npm dependency strategy: docs-site package.json pins an exact/caret version of @lempert/user-agent (starting at 0.2.0), bumped by hand in its own commit when the demo should pick up a new release -- never 'latest'. Keeps the live demo reproducible and reviewable rather than silently changing behavior on every npm publish.
- (decision) Repo/dependency boundary: docs site lives in its own top-level folder (docs-site/), a plain Node/Vite project entirely outside the Gradle multi-module build. It depends on the library ONLY via the published npm package (AD-7 of the library's initiative spine) -- never via in-repo Kotlin source, a Gradle project dependency, or a local file: dependency. Mirrors the existing library spine's AD-4 boundary (library depends on nothing beyond stdlib; consumers depend on the library, never the reverse) by treating the site as an external consumer, not an in-repo module.
- (decision) Deployment: GitHub Actions workflow using the official Pages pipeline -- actions/upload-pages-artifact@v4 to package the VitePress build output, actions/deploy-pages@v4 to publish it. Repo's Pages source set to 'GitHub Actions' (not a gh-pages branch). Triggered on push to master with a path filter on docs-site/** plus the workflow file itself, so unrelated library-only commits don't retrigger a site deploy.
- (version) VitePress stable latest verified via web search (Sep 2026): 1.6.4 (2.0 exists only as alpha, e.g. 2.0.0-alpha.19 -- not stable, not bound). actions/upload-pages-artifact and actions/deploy-pages verified current at v4 per GitHub's own docs/marketplace.

- (capability) CAP-1 Parse: parse a raw User-Agent string into structured data (browser name/version, rendering engine, OS name/version, device type/model). Success: parsing a representative sample set covering major browsers/OS/devices returns correct structured fields on every MVP target.
- (capability) CAP-2 Generate: build a valid User-Agent string from structured input data. Success: generated strings match known-good UA formats (or round-trip through CAP-1's parser) for supported browser/OS/device combinations.
- (capability) CAP-3 Common API: expose one common KMP API surface usable identically from Android, iOS, JVM, and JS consumers, with target-specific work hidden behind expect/actual or a common interface. Success: the same Kotlin call site compiles and returns correct parse/generate results on all four MVP targets.
- (capability) CAP-4 Publish: publish the library as an MIT-licensed multiplatform artifact consumable via standard package managers. Success: a fresh project can add the published dependency and successfully parse/generate a UA string on each MVP target.
- (constraint) License: MIT end-to-end; only permissive-licensed (MIT/Apache-2.0/BSD) 3rd-party dependencies allowed, no copyleft (GPL/LGPL), so downstream MIT consumers never inherit copyleft obligations (user decision).
- (constraint) MVP targets are Android, iOS, JVM/Desktop, and JS(Web) only; Wasm/WasmJs is explicitly deferred and not required for v1 (user decision).
- (constraint) The library may wrap existing 3rd-party UA-parsing/generation libraries per target to accelerate delivery, rather than building a from-scratch cross-platform detection database in v1.
- (constraint) Current repo (kmp-user-agent) is scaffolded as an application template (androidApp/iosApp/webApp + sharedLogic/sharedUI with Compose Multiplatform and a React web app), not a publishable library module -- architecture must introduce or restructure a library module suitable for Maven/npm publishing.
- (constraint) v1 favors shipping speed and pragmatic scope over exhaustive browser/OS/device coverage; broader detection coverage is explicit post-MVP iteration work.
- (non-goal) Not building an exhaustive, continuously-updated device/browser/bot detection database competitive with mature parsers (e.g. ua-parser-js level coverage) in v1 -- deferred to post-MVP iteration.
- (non-goal) Not a UA-string based analytics, bot-detection, or fraud-scoring product.
- (non-goal) Not shipping a UI or application; this is a library only, distinct from the existing app-template modules in this repo.
- (non-goal) Wasm/WasmJs target is out of scope for the v1 MVP.
- (decision) Success signal: v1 is done when the library is published (MIT license, permissive-only deps) to Maven Central (and npm if a separate JS artifact is needed) with a common API that parses and generates User-Agent strings correctly against a documented set of test UA strings, verified passing on Android, iOS, JVM, and JS targets.
